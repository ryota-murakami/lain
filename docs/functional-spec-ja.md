# Lain 機能仕様書 — 改修中の実装と検証範囲

更新日: 2026年11月10日。調査版の基準コミットは `89f5078e7e15a72d7e48dace9ca5ad82f5f57f27`。
本書は今回の開発ブランチの仕様を記述する。公開済み v0.1.1 の仕様や、検証完了宣言ではない。
作業状況・証拠・未検証事項は [進捗記録](goal-2026-11-09/PROGRESS.md) と [QA対応表](goal-2026-11-09/qa-matrix.md) を参照する。

## 1. 対象環境と構成

- Electron 45、React 19、Vite 8、Redux Toolkit / RTK Queryを使用する。
- 新しいmacOSビルドはmacOS 13以降、arm64・x64を対象とする。公開済みv0.1.1のmacOS 12対応と区別する。
- Linuxはx64のAppImage・debを対象とし、CIでの起動と主要操作を検証する。実行結果が未記録の環境を対応確認済みとはしない。
- 左にグループ・コレクション、中央に一覧、右に選択したブックマークの詳細を表示する。
- Windows、モバイル、完全なオフライン編集、バックアップ管理画面、ハイライト編集は今回の追加機能に含めない。

画面の文言は英語。起動時はAll Bookmarksを選び、項目の選択と詳細パネルをリセットする。表示形式、テーマ、ショートカットなどの設定は復元する。通常のAPI取得・更新にはネットワークが必要で、永続的なオフライン編集キューは持たない。

## 2. 認証・セッション

ログイン操作でRaindrop.ioのOAuthウィンドウを開き、リダイレクト先とstateを検証して認可コードを交換する。ビルドにOAuth設定がない場合は、ウィンドウを開く前に設定不足を表示する。

トークンはElectron safeStorageによって暗号化する。安全な暗号化が利用できない環境、特にLinuxのbasic_textバックエンドでは、トークンをメモリにだけ保持する。ログイン画面とGeneral設定に、再起動後の再ログインが必要なことを表示する。

同時に複数のAPI要求が発生しても、期限切れトークンの更新要求は共有する。認証サービスの一時的な障害では保存済み資格情報を削除しない。失効した更新トークンは再認証を要求する。通常APIの401では認証画面へ戻す。

General設定からログアウトできる。ログアウト・アカウント切り替え時にはAPIキャッシュ、検索履歴、選択状態、コレクションごとのローカル設定をクリアする。テーマやアプリ全体の既定表示は維持する。

アクセストークンはAPI要求のために認証IPCからレンダラーへ渡る。「トークンがレンダラーへ一切渡らない」という仕様ではない。IPCは送信元を検証し、外部URLはHTTP/HTTPSに限定する。

現時点の実アカウントQAでは既存の認可済み連携を隔離プロファイルへメモリ内注入している。これは実APIと画面操作の検証であり、新規OAuthログイン・配布版の認証復元の成功を意味しない。

## 3. ブックマークの作成・編集・削除

URL、タイトル、説明、種類、保存先、タグ、重要マーク、ノートを保存する。追加ダイアログは保存完了を待ち、失敗時には入力を残して再試行できる。URLのメタデータ取得は公式APIを使用し、古いURLへの応答や手入力済みの値が上書きされないようにする。

高さの低いウィンドウでは追加ダイアログを画面高に収め、入力欄だけを内部スクロールする。タイトル、閉じる操作、保存・取消、サーバーエラーは画面内に保つ。1024×642の検証画面で、ノート展開・入力検証・503後の再試行中も入力を保持し、ホイールとキーボードから操作できることを確認している。

詳細パネルでは編集内容を保持して保存する。編集中に別クライアントが同じ項目を更新しても、未保存入力を自動で置換しない。外部変更を読み直す操作を明示する。保存を待っている間にさらに入力した変更も保持する。

タグ入力は候補選択、IME入力、重複の抑止を扱う。通常の削除はサービスのTrashへ移動する。失敗時に成功として詳細を閉じない。

新規登録はツールバーの追加ボタンまたは⌘Nから開く。URLは必須で形式を検証し、タグは空白を除去して小文字にそろえる。種類はlink / article / image / video / document / audioから選ぶ。Auto Iconは登録フォーム内のプレビュー設定で、ブックマークの保存フィールドには含めない。

詳細パネルでは保存済みカバー、ハイライト、作成日時、更新日時を閲覧できる。URL欄の「Copy URL」は現在入力しているURLをコピーし、「Open in browser」は外部ブラウザーで開く。Grid・List・Tableの項目メニューにもコピーと外部表示があり、一覧のダブルクリックまたはEnterでも開ける。外部起動はHTTP/HTTPSに限定する。詳細を閉じた後は保持している選択を再表示でき、未保存編集を伴う選択変更・閉じる操作は破棄確認を行う。

faviconは取得できなければ種類アイコンや文字表示で補う。Google Faviconを使用する場合は対象ドメインがGoogleへ送信される。ハイライトの編集、カバー画像アップロード、永久保存コピーを開く専用UIはない。

## 4. 検索と一覧

現在のコレクションと全ブックマークの検索範囲を区別する。URL・タイトル・説明の項目別検索、検索履歴、コレクションのあいまい検索を提供する。入力からサーバー検索まで300ms待ち、入力のたびに大量の要求を送らない。

| 対象項目         | 検索方法                                                        |
| ---------------- | --------------------------------------------------------------- |
| All Fields       | 入力をRaindropの検索APIへ渡す                                   |
| URL Only         | APIの`link:`条件を使い、取得結果のURL・ドメインを追加で絞り込む |
| Title Only       | APIの検索結果をタイトルの部分一致で絞り込む                     |
| Description Only | APIの検索結果を説明またはノートの部分一致で絞り込む             |

追加の部分一致は大文字・小文字を区別しない。APIが返さなかった項目まで端末側で検索する機能ではない。検索パレットの⌘Kは現在の範囲を引き継ぎ、⌘⇧Fは全体検索に切り替えて開く。結果を選ぶと詳細を開いてパレットを閉じる。検索履歴は空文字を除き、重複なし・新しい順で最大20件を保存し、全消去できる。サイドバーと保存先選択の名前検索はFuse.jsのあいまい一致と一致箇所の強調表示を使う。

APIの取得単位は50件。追加読み込みしたページを保持し、表示件数・取得済み件数・総件数を区別する。検索パレットには追加読み込みを用意し、先頭20件だけを全結果のように表示しない。全選択は現在の表示対象に対応する。

Grid・List・Table・Directoryを切り替えられる。コレクション別指定を優先し、指定がない場合はGeneralのDefault Viewを使う。選択した表示形式は再起動後も復元する。

Gridはカバー付きカード、Listは行、Tableは列、Directoryはフォルダーツリーで表示する。選択対象があるときは詳細パネルで内容を確認できる。「Remember for this collection」を有効にした保存先では、その保存先の表示形式だけを変更し、無効にすると全体の既定表示へ戻る。

| 一覧ツールバーの並び順 | APIへ指定する順序     |
| ---------------------- | --------------------- |
| Newest First           | 作成日時の新しい順    |
| Oldest First           | 作成日時の古い順      |
| Title A-Z / Title Z-A  | タイトルの昇順 / 降順 |
| By Domain              | ドメイン順            |
| By Relevance           | 関連度順              |
| Manual Order           | 手動順                |

この並び順は画面内の状態で、再起動時はNewest Firstに戻る。検索・保存先・並び順を変えると、その条件のページ取得へ切り替わる。通常は末尾へのスクロールで追加取得し、Load moreからも操作できる。

Tableはサービスの並び順を初期値とする。列ソートは読み込み済み項目に対する操作であることを説明し、サービス順へ戻せる。絞り込みや削除でページが存在しなくなったら、有効なページへ移動する。ページ単位の選択操作で別ページの選択を失わない。

Tableの表示は1ページ50件。タイトル、ドメイン、種類、作成日時、更新日時で列ソートでき、列の表示も切り替えられる。列設定・ページ位置・列ソートはTable内の状態で、再起動後に復元する設定ではない。

Directoryは親子関係と空のコレクションを表示する。全展開・全折りたたみをすべての階層へ適用し、ブックマークの複数選択・一括操作を可能にする。不正な循環や重複した階層が返っても無限再帰しない。

Directoryも取得済みブックマークを表示する。全フォルダーの未取得項目を一括で読み込む意味ではない。サイドバーのコレクション展開は保存対象だが、Directoryの展開操作はそのビュー内の状態である。

## 5. コレクション・グループ・一括操作

コレクション作成・設定画面ではグループ、親、色、アイコン、既定表示、公開設定を扱う。名前・親・グループ・公開設定はRaindropへ保存し、色・アイコン・表示指定はこの端末のLainアカウント設定へ保存する。Raindrop APIのコレクション色はカバーから生成されるため、Lainで選んだ色をサービスの色として書き戻さない。自身や子孫を親に選べない。

All Bookmarks、Unsorted、Trashは常に表示するシステム保存先で、APIのIDはそれぞれ`0`、`-1`、`-99`。コレクションは右クリックメニューから設定、名前変更、グループ移動、色変更、削除を操作する。ルートコレクションは名前のダブルクリックでも変更でき、子コレクションの設定はその項目のCollection Settingsから開く。

グループの追加・編集・削除を画面から行える。グループ削除はコレクションの意図しない削除を引き起こさない。失敗時には編集内容を残す。グループの折りたたみ状態とコレクションの展開状態を復元する。

サイドバー下部のNew Groupから作成し、各グループの操作メニューで編集・削除する。グループ内のAdd Collectionはそのグループを初期保存先にし、一般の作成操作は最初の実在グループを選ぶ。編集時は既存の所属を保持し、親コレクションを選ぶ場合は親のグループを優先する。実在するグループの折りたたみ状態はサービスへ、コレクションの展開状態はLainへ保存する。仮想グループOther collectionsの折りたたみだけは現在の画面内に保持する。

APIのroot/children両方に同じコレクションが含まれても、画面では一度だけ表示する。グループに属さないコレクションは読み取り専用の仮想グループ「Other collections」に表示する。これはRaindropのグループとして書き戻さず、コレクション編集時には実在するグループを選ぶ。

各ビューの一括操作は選択項目を対象に、移動・タグ追加・削除を実行する。Tableには一括の「Mark Important」もあり、全選択項目を重要にそろえる。Grid・Listの項目メニューや詳細の重要指定は個別トグルであり、一括重要化とは区別する。複数の元コレクションを処理する場合、一部成功後の再試行が成功済み項目を二重操作しないよう、未完了項目を保持する。削除失敗を未処理のPromise rejectionとして残さず、再試行案内を表示する。

Grid・Listでは⌘/Ctrlクリックで選択を追加・解除し、Shiftクリックで選択中の項目からの範囲を選ぶ。各ビューのチェックボックスも同じ複数選択へ反映する。⌘Aは現在のビューに描画されている項目を対象とし、Tableの別ページ、閉じたDirectory階層、サーバー上の未取得項目は追加しない。

| ドラッグ操作                 | 対象・条件                                                                                     |
| ---------------------------- | ---------------------------------------------------------------------------------------------- |
| ブックマークの保存先変更     | Grid・ListからコレクションまたはUnsortedへドロップ。選択中の項目をつかむと選択IDをまとめて移動 |
| ブックマークの手動並べ替え   | Grid・List、Manual Order、検索語が空、All Bookmarks以外                                        |
| コレクションの移動・並べ替え | ルートコレクションのグループ間移動と同一グループ内の順序変更                                   |

ドラッグ中はプレビュー、移動先、挿入位置を表示し、失敗した楽観更新は戻す。Table・Directoryのブックマークドラッグと、ドラッグによる任意の親子付け替えはない。親の変更にはCollection Settingsを使う。

**コレクション統合:** サイドバー下部のMerge Collectionsで統合元・統合先を選び、元のブックマークを先へ移して元を削除する。子コレクションを含む全階層を候補にし、親からのパスで同名を区別する。統合先が元自身またはその子孫になる選択は禁止し、画面に理由を表示する。処理中は二重送信と閉じる操作を防ぐ。成功を待って閉じ、失敗時には両方の選択を残す。タグ統合とは別の操作で、実アカウントの受け入れ結果はQA項目C06を参照する。

**ゴミ箱を空にする:** Trash行のメニューにEmpty Trashがあり、`DELETE /collection/-99`を実行する。これはTrash全体を対象にした永久削除で、通常のブックマーク削除とは異なる。通信エラーとHTTP 200の`result:false`は失敗として扱い、エラー通知を1件表示して再試行できる状態を保つ。今回のQAでは原本を含む実アカウントでは実行しない。API契約に加え、隔離した合成データで実メニューからの成功・拒否・表示更新・未処理エラーがないことを検証し、実アカウント検証済みには数えない（C07）。

タグ管理では対象範囲を明示する。名称変更・削除・統合はAPI完了を待ち、失敗時の再試行を用意する。統合は複数のタグを1つの更新で対象名へ集約する。

Manage Tagsまたは⌘⇧Tから開き、名前・使用件数の一覧、名前による検索、名前順・使用件数順の並べ替え、単一または選択したタグの削除を操作する。この管理画面の一覧と変更は全ブックマークを対象にそろえる。ブックマークの登録・詳細では、その項目のタグを追加・削除する。

## 6. 同期と通信

Raindropの公開APIで利用できる変更マーカーとポーリングを使用する。独自のWebSocketやWebhookは仮定しない。

- アクティブ時は統計・ブックマーク変更マーカーを3秒間隔、ユーザー・コレクション階層を4秒間隔で確認する。
- フォーカス復帰・再接続時は更新し、オフラインでは周期的な確認を止める。
- 作成・編集・削除は関連する一覧、件数、検索、タグのキャッシュを無効化する。
- 同期状態、最終同期、失敗と手動更新を画面へ表示する。
- 共有の要求予算を90回/分とし、公式上限120回/分に余裕を残す。429のリセット時刻を待ち、待機中の要求も新しいリセットを再確認する。書き込みの自動再送はしない。

実アカウントの独立した3回の外部編集は1,538ms・2,072ms・3,120msで表示された。これは通常時の限定した測定であり、常に5秒以下という保証ではない。大量エクスポート、レート制限、回線障害、非アクティブ時には遅延が増える。最終ビルドでの測定はQA結果を確認する。

## 7. 全件エクスポート

ツールバーから全ブックマーク、または指定コレクションと子孫を選び、JSON・HTML・CSVを保存する。Trashは全ブックマークに含めない。全ページを取得し、件数・重複ID・変更マーカー・階層メタデータを確認する。取得中に内容が変化した場合は部分データを成功扱いしない。

取得中は進捗を表示し、中止・失敗後の再試行を提供する。保存先はネイティブのダイアログで選択する。同じ保存先フォルダーに一時ファイルを書き、完成した内容を置き換える。ネイティブ保存段階ではOSの保存ダイアログのキャンセル操作を使う。

| 形式 | 保持する内容・制約                                                                                                 |
| ---- | ------------------------------------------------------------------------------------------------------------------ |
| JSON | 取得したブックマークとコレクション・グループのメタデータ。スキーマバージョンを付ける                               |
| HTML | Netscape形式のフォルダー階層、URL、タイトル、説明、タグ等。HTML文字をエスケープする                                |
| CSV  | 表形式のURL、タイトル、説明、ノート、タグ、重要指定等。BOM・引用・改行を処理し、数式として解釈される値を無害化する |

添付ファイル本体、永久保存コピー、別エンドポイントのハイライト、サービス設定の完全復元を保証するバックアップではない。各形式の詳細は[エクスポート検証](goal-2026-11-09/export-validation.md)を参照する。

## 8. ファイルアップロード

ファイル選択またはドラッグ＆ドロップから複数ファイルをキューへ追加する。保存先、各ファイルのタイトル、共通のタグ・ノート・重要指定を編集できる。同じローカルファイルの重複追加を抑止する。

JPEG/JPG、GIF、PNG、WebP、HEIC、MP4、MOV、WMV、WebM、MP3、WAV、AIFF、FLAC、EPUB、PDF、MD、TXTを扱う。空ファイル、未対応形式、1ファイル当たりの上限、残り月間容量を送信前に確認する。Freeの1ファイル上限は100MB、Proは300MB。アカウントの最新月間使用量・上限を取得し、最終的な受理はサービス側の判断に従う。

転送は順番に進め、進捗・中止・ファイルごとの結果を表示する。ファイル作成後のメタデータ保存が失敗した場合は、受領済みIDへ再試行し、ファイルを重複作成しない。応答が途切れて作成成否が分からない場合は、自動再送せず、保存先に存在しないことを利用者が確認した後に再試行する。

## 9. 設定・ショートカット・アイコン

Generalにテーマ、Default View、ログアウトを用意する。キーボード設定は割り当ての競合、交換、初期化を扱う。Linuxでは既定のCommand操作をControlとして扱い、表示名と衝突判定も一致させる。通常の入力欄・IMEの編集を妨げない。Escapeなど固定の操作は変更できない理由を表示する。

テーマはLight / Dark / Systemから選ぶ。初期値はSystemで、OSのテーマ変更に追従する。サイドバー下部のToggle themeからも切り替えられる。設定は⌘,、ショートカット編集は⌘⇧Kから開く。

| 操作                            | macOSの既定キー   | 対象                                     |
| ------------------------------- | ----------------- | ---------------------------------------- |
| 検索パレット                    | ⌘K                | 現在の検索範囲を引き継ぐ                 |
| 一覧の検索欄へ移動              | ⌘F                | 検索範囲は変更しない                     |
| 全体検索パレット                | ⌘⇧F               | 全コレクション検索へ切り替える           |
| 上／下へ移動                    | ↑ / ↓             | 現在のビューの表示順に項目へフォーカス   |
| URLを外部表示                   | Enter             | 一覧の対象項目                           |
| 詳細パネルを切り替え            | Space             | 一覧の対象項目                           |
| パネル・ダイアログを閉じる      | Escape            | 固定キー。各ダイアログの保存中制約に従う |
| 新規ブックマーク                | ⌘N                | 追加ダイアログ                           |
| 新規コレクション                | ⌘⇧N               | 作成ダイアログ                           |
| 選択項目の削除                  | ⌘Backspace        | 複数選択、または現在の選択項目           |
| 全選択                          | ⌘A                | 現在のビューに描画されている項目         |
| 重要マーク切り替え              | ⌘D                | 単一の選択項目                           |
| タグ管理                        | ⌘⇧T               | 全ブックマークのタグ管理                 |
| Grid / List / Table / Directory | ⌘1 / ⌘2 / ⌘3 / ⌘4 | 表示形式の切り替え                       |
| 設定                            | ⌘,                | Generalタブ                              |
| ショートカット編集              | ⌘⇧K               | Keyboard Shortcutsタブ                   |

Linuxでは表中の⌘をCtrlに読み替える。↑/↓、Enter、Spaceは一覧のナビゲーションで使い、入力欄やポータルのメニュー操作を奪わない。キー記録では修飾キーのみの入力や予約キーを拒否し、競合を解決するか交換して保存する。カスタム割り当ては再起動後も復元し、Reset to Defaultsで初期値へ戻せる。

IconsタブでI01〜I64を比較し、16/32/64/128pxおよび明暗背景で確認する。適用した選択は保存し、初期アイコンへ戻せる。macOSはDock、Linuxはウィンドウアイコンへの反映であり、署名済みアプリのバンドルやLinuxのランチャーファイルを実行時に書き換えるものではない。

## 10. 更新・配布と検証境界

Settings → Updatesに現在版、手動確認、確認中、最新版、更新あり、任意のダウンロード、進捗、準備完了、再起動して適用、Later、失敗・再試行を表示する。二重要求を抑止し、未保存作業・転送がある場合には再起動を実行しない。通常終了だけでは更新を適用しない。

macOSとAppImageはそれぞれの更新機構を使用する。debはパッケージの取得・インストール手順を案内し、AppImageと同じ自動更新を実行したようには表示しない。

macOSの署名・公証、Linuxパッケージ、実際の旧版→新版置換、再起動後のデータ保持、CIの最終ソース検証は[配布検証記録](goal-2026-11-09/release.md)を参照する。設定ファイルの存在や単体テストだけでは、実配布と更新の成功を意味しない。

## 11. デザイン候補と採用

WebはW01〜W12の独立した実ページを非公開Siteで比較する。64アイコンは個別画像・比較シート・アプリ内プレビューを提供する。推奨順位は比較資料に記載し、採用案は利用者が選ぶ。本番Webサイトのデザインを候補へ自動で置き換えない。

## 12. 検証に関する扱い

実アカウントQAは検証済みバックアップ作成後に開始し、専用コレクションと無害なデータだけを書き換える。後片付けは専用の台帳に記録したデータに限定する。共有するスクリーンショット・動画は合成データを使い、実アカウントの証拠は非公開のローカル領域へ保管する。

動き・ドラッグ・複数ステップ操作は動画を記録して抽出フレームを確認する。DOMテスト、モックAPI、実API、ネイティブOS、パッケージ起動の証拠は区別する。未実行・失敗・外部認証待ちはPASSと記載しない。
