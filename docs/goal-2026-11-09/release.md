## Implemented workflow and source identity

- PR packages are unsigned and use no signing secrets. Package CI checks out the immutable PR head SHA, embeds it in ASAR and records a clean source tree.
- Tag release accepts the exact `v` + package version, runs quality gates, signs/notarizes macOS builds, staples DMGs, regenerates metadata and verifies provenance before publishing. This configured route has not been exercised as a production release.
- Manual execution provides unpublished artifacts and an optional QA draft tagged `qa-v<version>-<run id>`, excluded from the production feed. Signing is opt-in and fails when required credentials are absent. A newly added workflow must be available to GitHub before its dispatch route can run; no merge is authorized merely to enable dispatch.
- Every packaging run deletes prior output and rebuilds it. Verification checks version, source, package names, SHA-512 feed hashes, SHA-256 checksums and both macOS ZIP blockmaps. Linux names use electron-builder's observed `x86_64.AppImage` and `amd64.deb` suffixes.
- Local unsigned development packages may record a dirty tree, but the normal release verifier rejects that state. CI and signed packaging require a clean tree.
- macOS Intel artifacts passed build/content/hash verification. Native Intel GUI execution has not been performed; arm64 smoke does not establish it.
- Linux native execution is confirmed on Ubuntu 24.04 x64 with Xvfb and synthetic APIs. AppImage smoke used extraction mode; this is not evidence of FUSE integration or an old-to-new AppImage update.

Six release-integrity tests cover valid output and rejection of tampering, wrong source, stale packages, traversal and dirty manifests. Fifteen support-script tests cover requirement accounting, post-stapling hashes, blockmap retention, idempotency, missing artifacts, accepted-notary enforcement and redacted subprocess failures. Apple calls in those support tests are mocked.

## Native update contract and executed evidence

One main-process state machine coalesces timer and IPC requests. `autoDownload` and `autoInstallOnAppQuit` are false. Restart requires no pending edits/transfers and native confirmation; Later keeps the verified download ready. Ordinary test/development profiles never contact a release feed. Linux AppImage uses in-app updates; deb opens the fixed official download page for explicit installation.

Its guard requires a packaged QA version, synthetic authentication, an archive inside the fixture workspace and an explicit `127.0.0.1` feed. It does not edit the production version or publish a tag. The initial build is snapshotted; subsequent packaging does not reread repository `dist`. QA builds retain English/Japanese Electron locales; production keeps all locales.

## Failures reproduced and corrected

- Initial local package startup lacked the `/user/stats` fixture and showed a white renderer. The fixture and defensive read were fixed; package smoke now rejects renderer exceptions and console errors. Synthetic favicon responses are deterministic while bundled assets and application logic remain real.
- Electron's [about: navigation event gap](https://github.com/electron/electron/issues/21136) bypassed `will-navigate`. Deferred recovery after document commit restored the exact trusted renderer; popup denial, recovery and loaded-library assertions passed. IPC for authentication, external links, export, appearance and updates requires the active window, main frame and exact document URL.
- First hosted native smoke lost its primary error when failure screenshot capture timed out. The runner now saves the original error/stage first and separately records optional evidence-capture failure. A controlled negative test verifies this behavior.
- Recorded CI cases failed with missing Playwright-managed ffmpeg. An empty private browser cache reproduced the reload timeout and missing-video error; installing only that ffmpeg dependency made the same case pass. Both workflows now install it. Visible windows remain enabled on macOS and in Linux Xvfb.
- A local run of the downloaded ARM app blocked in macOS Keychain, confirmed by process sampling. Ordinary synthetic test mode now stays session-only without probing Keychain; production and strict update QA retain native encryption. This is a separate proven fixture defect, not a retrospective explanation of the lost original hosted error.
- Menu/dialog closing races were fixed with explicit transition waits and view assertions. Linux-specific unit assumptions, missing Debian maintainer attribution and incorrect Linux filename expectations were corrected without weakening checks. The successful hosted `fdc17c3` runs above validate these CI repairs.
- Visual review then found List focus scrolling outside the viewport, Linux's hardcoded Command search hint, and an upload retry leaving a contradictory global error toast. Each has reproduced regressions and local fixes. Toolbar overflow and long-tag List title compression at 1024px with detail open also received local corrections. Final integrated validation must include those later changes.
